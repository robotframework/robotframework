# Libdoc frontend

The HTML page Libdoc generates for a library's documentation. Everything on it
is either written by the library author or generated by the frontend from the
library's specification, and the two need different names, because the frontend
can choose the shape of what it generates and cannot choose the shape of what it
is given.

## Language

### Tables

**Documentation table**:
A table a library author wrote inside a docstring, in whatever documentation
format that library uses. Its content, width and column count are the author's.
_Avoid_: doc table, content table, author table

**Data table**:
A documentation table holding genuine tabular data, usually short keys against
prose, read by looking a row up rather than reading across.
_Avoid_: real table, proper table

**Layout table**:
A documentation table used to lay Robot data out in columns, where the table is
a code sample and the column alignment carries the meaning. Wrapping a cell
destroys it.
_Avoid_: example table, code table, fake table

**Keyword info table**:
A table the frontend generates for one keyword, listing its arguments, its return
value or the exceptions it raises.
_Avoid_: argument table (that is one of the three), signature table

**Metadata table**:
The table of library-level facts shown under the title, such as version and
scope.

### Formats and fixtures

**Documentation format**:
The syntax a library's docstrings are written in, declared by the library and
fixed for all of it. ROBOT is the default, which is why layout tables are common
in third-party libraries: that format has no fenced code blocks, so a table is
the only way to lay Robot data out in columns.
_Avoid_: doc format, markup

**Development fixture**:
A library that exists only to be rendered while working on the frontend, and the
generated specification it produces. There is one per documentation format,
because a library has only one.
_Avoid_: test data, demo library, sample library
